static int IN1 = 2;
static int IN2 = 3;
static int SERVO_PIN = 6;
// deine motor control pins and servo control pin, using the GPIO pin index in xiao esp32s3

Servo steering; //create steering object that connect to the ESP32Servo libiary

#define SERVICE_UUID        "12345678-1234-1234-1234-123456789abc" // Store the blue tooth SERVICE_UUID for esp-32 board
#define CHARACTERISTIC_UUID "abcd1234-1234-1234-1234-abcdef123456" // Store the blue tooth CHARACTERISTIC_UUID for esp-32 board

class MyServerCallbacks : public BLEServerCallbacks { // Create a class called MyServerCallbacks, and use it to override the BLE library’s default callback functions
  void onConnect(BLEServer* pServer) { // When connected to phone
    deviceConnected = true; // Write deviceConnected as True
  }
  void onDisconnect(BLEServer* pServer) { // When disconnected to phone
    deviceConnected = false; // Write deviceConnected as False
  }
};

// MOTOR CONTROL FUNCTIONS
void forward() { // send high to IN1 which is connected to 1A in the H bridge so both motor power forwards
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, LOW);
}

void backward() { // send high to IN2 which is connected to 2A in the H bridge so both motor power backwards
  digitalWrite(IN1, LOW);
  digitalWrite(IN2, HIGH);
}

void stopMotors() { // send low to both gate in H bridge so motor stop moving, and send 90° to servo so it become neutral
  analogWrite(IN1, LOW);
  analogWrite(IN2, LOW);
  steering.write(90);
}

void left() { // send 160° to the servo so it turn left
  steering.write(160);
}

void right() { // send 20° to the servo so it turn right
  steering.write(20);
}
// MOTOR CONTROL FUNCTIONS OVER

class MyCallbacks : public BLECharacteristicCallbacks { // Create a class called MyCallbacks, and use it to override the BLE library’s default callback functions
  void onWrite(BLECharacteristic *pCharacteristic) {  // ESP32 BLE library calls this function internally whenever the board detect data from phone
    String value = pCharacteristic->getValue(); // Store the value from phone
    char cmd = value[0]; // First character of the BLE message
    Serial.println(cmd); // Print command to the serial port

      if (cmd == 'F') {
        Serial.println("Forward");
        forward();
      }
      if (cmd == 'B') {
        Serial.println("Backward");
        backward();
      }
      if (cmd == 'L') { 
        Serial.println("Left");
        left();
        }
      if (cmd == 'R') {
        Serial.println("Right");
        right();
      }
      if (cmd == 'S') { 
        Serial.println("Stop"); 
        stopMotors();
      }
      //print movement to the serial port and call specfic motor control function to send command to the motors
  }
};

void setup() {
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
  //set motor pins as OUTPUT
  steering.attach(SERVO_PIN); // Attach the servo libiary to the servo pin
  steering.write(90); // Set steering to neutral

  Serial.begin(115200); // Start Serial communication

  BLEDevice::init("ESP32_Car"); // Name of the esp32 that's will show up on the scanner, and initializes BLE connection
  BLEServer *pServer = BLEDevice::createServer(); // Create BLE server
  pServer->setCallbacks(new MyServerCallbacks()); // connect MyServerCallbacks to this call

  BLEService *pService = pServer->createService(SERVICE_UUID); // Create BLE device for esp32 board

  pCharacteristic = pService->createCharacteristic(
                      CHARACTERISTIC_UUID,
                      BLECharacteristic::PROPERTY_WRITE
                    ); // Set esp32 board as something that server device can write to

  pCharacteristic->setCallbacks(new MyCallbacks()); // direct command from the phone to MyCallBack class
  pService->start(); // start the BLE service
  pServer->getAdvertising()->start(); // make esp32 disvoerable to other devices

  Serial.println("BLE Car Ready"); // print message that esp32 is ready
}

void loop() {} // Not needed for BLE connection in eps32, since its event-driven

Technical Write-up:

My project focuses on creating a fully remote-controlled toy car, consisting of two main components: a wireless remote control and the car itself, which can move forward, backward, and turn left or right.
For the remote control, I used an ESP32-S3 board, which includes built-in Bluetooth and Wi-Fi. I set the ESP32-S3 board as the client so it can receive commands from a smartphone app via Bluetooth. I used the "BLE Scanner" app on my phone to send simple single-character commands ('F' for forward, 'B' for backward, 'L' for left, 'R' for right, and 'S' for stop).
For the movement system, the car uses two DC motors for propulsion and a servo motor for steering. The DC motors are driven by an H-bridge, which controls motor direction based on the input signals it receives—for example, a HIGH signal on 1A and a LOW signal on 2A will rotate the motor clockwise.
The servo motor is connected directly to the ESP32-S3, which controls its position by sending PWM signals.


Challenges I Encountered:

1. No existing 3D model:
When I started the project, I expected to find a pre-made 3D model of an ESP32-S3 controlled toy car that I could simply download and print. Unfortunately, none existed, so I had to design everything from scratch. The mechanical components—especially the steering mechanism—took the most time. Designing the frame and ensuring that all the parts fit together properly also required a lot of iteration. I ended up spending my entire Thanksgiving break creating the 3D model for the car.


Lesson learned from this
I’m really proud that I designed a fully functional 3D-printed toy car. However, for the scope of a class project, I should have done more research and created a time estimate for each major component before starting. If I had known certain parts would take significantly longer, I would have preferred to pivot early rather than rush to building a half-working prototype.


2. 6V Motor doesn't have enough torque to power the car


During testing, I found that the 6V DC motors I used didn’t provide enough torque to move the car. I was frustrated because I had already 3D printed the entire car frame and assembled all the components. I was planning to switch to a 12V motor, but the size difference between them means that the new motor will not fit in the frame. I had to design a new model but I didn't have time to print it and implemented it


Lesson learned from this
In the future, I will prototype and test all mechanical components before finalizing the design. This way, I can ensure that everything works as intended and avoid last-minute changes that could jeopardize the project timeline.


3. Power comsumption when using batteries is abysmal


During testing, I found that the motors drained 9V batteries extremely quickly—one battery lasted less than five minutes when both motors were running at full power. Since each 9V battery costs about $4, I switched to an external power supply for testing. Going forward, I think using rechargeable batteries would be a better solution, and I plan to implement that as I improve the project after this class.


Lesson learned from this
In the future, I will calculate the expected power consumption of all components before selecting a power source. This will help me choose batteries or power supplies that can meet the project's needs without frequent replacements.
